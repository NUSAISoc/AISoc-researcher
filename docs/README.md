# Documentation

This folder is the complete, ordered documentation of the research process. Unlike a running list of notes, it holds one file per step of the research, and each file is the current, authoritative version of that step. When a step changes, its file is updated in place and the superseded content is deleted (dated records like `00-beryl-provenance.md` are the audit-trail exception).

Problem and solution work uses the Beryl [Systems Thinking Methodology](../.beryl/agent/systems-thinking-methodology.md). The methodology requires a system boundary, feedback structure, delays, assumptions, and a leverage hypothesis before an intervention is proposed.

This is a working space, not a user-facing surface. The user reads `ProjectProposal.md`, `report/`, and `notes/`; this folder holds the detailed process behind them.

Every file below ships as a fork template. Replace its placeholders with your study and keep it synchronized with the other targets named in the [Synchronization Contract](../.beryl/agent/synchronization-contract.md).

## Conventions

- Keep exactly one current version of each step. Update in place; delete superseded text.
- Date any document that changes a settled decision and preserve the superseded version only in that dated record.
- Keep each prose paragraph on one physical source line.
- No em-dashes.
